# 设计文档规则

## 设计取向

围绕高内聚、低耦合组织架构和模块。让模块职责集中、依赖方向清晰，并为新增格式、场量、算法或外部接口预留可扩展位置；可借鉴开闭原则，即通过扩展支持变化，尽量避免修改稳定核心。该原则不依赖面向对象设计。设计报告以总体架构和模块关系为重点，技术路线、接口和数据结构用于支撑该重点。

## 推荐结构

1. 技术路线：说明主要语言、框架、运行环境、关键第三方组件及选型理由。
2. 架构设计：说明分层或组件边界，并给出总体架构图。
3. 系统运行流程：描述输入进入、主要模块协作、输出产生和错误反馈的顺序。
4. 模块设计：说明每个模块的职责、依赖、输入和输出，并给出模块关系连接图。
5. 接口设计与数据结构设计：先用简表说明模块提供的接口组、主要数据对象及其用途；任务未要求时，不罗列所有字段和全部内部接口。
6. 数据库设计：仅在使用关系型数据库时，补充实体关系和 ER 图。

## 模块与接口

模块间连线表示内部接口组，应标明必要的数据或调用方向。模块与文件、命令行、第三方系统、用户界面等外部对象的连线表示外部接口组。优先减少跨模块直接访问，保留少量、清晰且稳定的连接，使耦合关系可读。

接口简表至少包含接口组名称、提供方、使用方、用途及主要输入输出。数据结构简表至少包含数据名称、归属模块、用途和关键内容；没有明确需求时，不提前固定字段、类型或存储细节。

## 审阅要点

- 架构图、模块关系图、运行流程和接口表描述同一依赖关系。
- 模块职责没有重复且边界可解释；变化点与稳定核心分离。
- 用户功能需求可追溯到设计支持，但两者不要求同名或一一对应。
- 设计结论基于现有代码、技术约束或明确假设，并标出未确认内容。
